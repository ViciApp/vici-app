# Satellite testing

## What exists today

- **Few satellite unit tests.** `npm test` runs the pure-logic specs under `src/tests/` (Node's runner, `tsx --test`); `src/tests/satellite/` holds the few that cover `src/satellite/`: specs of pure helpers in `src/satellite/utils/` that import nothing from `@junobuild/functions` at runtime, and of asserts whose host reads are stubbed as shown below. The one `@junobuild/functions` host stand-in is `src/tests/mocks/satellite-host.mock.ts` (below).
- **The satellite is covered end to end** by the Juno Playwright suite against the emulator (`npm run e2e`, see [`frontend/testing.md`](../frontend/testing.md#e2e-playwright)), and the engine wiring by `npm run test:engine-sync` (`scripts/test/test-engine-sync.sh`).
- **The build is a check too.** `npm run juno:functions:build` must succeed and leave no drift; CI's `satellite-schema` job fails on any.

## Adding a test

- Pure satellite logic (validation, diffing, wire conversion) that imports nothing from `@junobuild/functions` can be specced today: put it under `src/tests/satellite/<path>.spec.ts`, mirroring `src/satellite/`, with `node:test` and `node:assert/strict`, as the specs under `src/tests/lib/` do.
- An assert whose host reads are `getAdminAccessKeys()` (a controller check) and `decodeDocData` can be specced by defining the globals the SDK calls, `__juno_satellite_get_admin_access_keys` and `__juno_satellite_datastore_raw_data_to_text` (a `TextDecoder` decode), and removing them after each test: see `src/tests/satellite/services/vxp-awards.services.spec.ts` (the controller check alone) and `src/tests/satellite/services/tournament.services.spec.ts`. Build doc bytes with `TextEncoder`, since `encodeDocData` is a host call too.
- `src/tests/mocks/satellite-host.mock.ts` holds those globals for reuse, and builds `AssertSetDocContext` / `AssertDeleteDocContext` values: `installSatelliteHost({ docs, createdAtNs })` in `beforeEach` (`docs` and `createdAtNs` seed the datastore), its `restore()` in `afterEach`. `src/tests/satellite/index.spec.ts` runs contexts through the `assertSetDoc` / `assertDeleteDoc` dispatch itself and checks that every `write: 'public'` collection in `juno.config.ts` has both asserts.
- Logic tangled with `getDocStore` / `setDocStore` is best split: extract the pure part into a function (that is the seam) and spec it. When the behaviour under test is the I/O path itself (what an endpoint pays, from which docs and canister answers), drive the real service through the same host: an in-memory datastore, caller (`setCaller`), clock (`setNowMs`) and canister-method table (`onCall`) behind the host globals. Asserts and hooks do not run there, so seed only docs the real asserts accept. Reference: `src/tests/satellite/services/vxp-worlds-podium.services.spec.ts`. Do not add a mocking library without approval.
- A hook or endpoint change is verified on the emulator: deploy with `npm run juno:functions:upgrade:dev` and describe the manual steps in the PR's `# Tests`.
