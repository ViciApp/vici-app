# Accessibility (a11y)

**Accessibility is non-negotiable.** This page is the contract for
keyboard, semantic, contrast, and ARIA rules. For anything that involves
**user-visible strings**, the contract is
[`i18n.md`](./i18n.md): read it together with this page.

## Copy & strings: see [`i18n.md`](./i18n.md)

The repo has a typed i18n layer:

- All user-visible copy goes through
  `t({ locale: $localeStore, key })` from `#lib/utils/i18n.utils.ts`.
- Locales are declared in
  [`#lib/constants/locale.constants.ts`](../../../src/lib/constants/locale.constants.ts)
  (`LOCALE_REGISTRY` is the full source of truth; the live, picker-offered
  set is `en, es, pt, it, fr, de, zh-Hans`).
- Catalogs live in `src/lib/constants/messages/<locale>.ts` and are
  key-aligned (drift fails CI via `npm run check:i18n`).
- The ESLint rule `local-rules/no-bare-svelte-text` flags hardcoded text
  inside `.svelte` files that already import `i18n.utils`.

The a11y-specific points about copy:

- **Brand / token names are exempt** from translation. `Vici`,
  `Internet Computer`, `BTC`, `ICP`, `ckUSDC`, `Bitcoin` etc. stay
  literal; don't add catalog keys for them.
- **Internal logs / error messages** are not user-visible and don't need
  to be translated. Keep them readable for engineers.
- **`aria-label` / `alt` / `aria-describedby` are user-visible.** They
  must come from a catalog key, not from a hardcoded English string.
- **No magic concatenation.** Never build sentences with `+`. Use a
  single catalog key per phrase with `{named}` interpolations; `t(...)`
  handles substitution.

## Accessibility rules

Baseline rules: `svelte-check` and ESLint a11y rules catch some
violations.

### Semantics

- **Use the right element.** `<button>` for actions, `<a>` for navigation,
  `<label>` for inputs, `<h1..h6>` for hierarchy in order, `<nav>` /
  `<main>` / `<aside>` / `<header>` / `<footer>` for landmarks.
- **No bare clickable `<div>`s.** If you absolutely need a `<div>` /
  `<span>` for visual reasons, set `role`, `tabindex="0"`, and keyboard
  handlers (`onkeydown` for Enter / Space). Prefer the right element.

### Labels

- Every form input has a programmatic label. Either:
  - A `<label for="…">` paired with `id`, or
  - `aria-label` / `aria-labelledby`.
- Icon-only buttons need `aria-label` (or visible text via an `sr-only`
  span).
- Decorative icons → `aria-hidden="true"`.

### Focus & keyboard

- Don't kill focus outlines.
- Modals / drawers / popovers: use the existing primitives in
  `#lib/components/ui/` (`Modal`, `Dialog`, `PopOver`). They handle focus
  trap, escape, click-outside. Do not roll your own.
- Modal close button must be reachable by keyboard.
- For lists where the user picks one of N items, focus order matches
  visual order.

### Color & contrast

- Never communicate state with color alone: pair it with an icon, label,
  or shape.
- Use the project's design tokens from
  [`src/app.css`](../../../src/app.css) (`primary`, `background`, `card`,
  `card-border`, …) and the matching Tailwind utilities (`bg-card`,
  `text-card-foreground`, …). Never hard-code hex.

### Images / media

- Meaningful images: `alt="…"` describing the content.
- Decorative images: `alt=""` (empty, not omitted).
- SVG icons: see [Icons](#icons) below.

### Routing

- SvelteKit's file-based routes drive the document title. Set it from
  the matching `+page.svelte` or `+layout.svelte` and don't reach in
  and overwrite it from a deeply nested child component.
- `target="_blank"` requires `rel="noopener noreferrer"`.

### Icons

- Default to `@lucide/svelte`; bespoke icons live under
  `#lib/components/icons/`.
- Decorative icons inside a labelled control get `aria-hidden="true"`.
- Icon-only controls get `aria-label="…"` on the button (not on the
  icon).

### ARIA: minimum surface

Use ARIA only when HTML semantics are insufficient. If you find yourself
writing `role="button"`, the answer is almost always to use a real
`<button>` instead.

## HTML safety

- Any HTML coming from backend / user input must be sanitised before
  `{@html …}`. There is no app-wide sanitiser yet; if you need one,
  surface the question in the PR description before adding a dependency.
- External links: `target="_blank"` requires `rel="noopener noreferrer"`.

## Quick checklist (every UI change)

- [ ] Every interactive element is a real `<button>` / `<a>` / primitive
      from `#lib/components/ui/`.
- [ ] Every input has a label or `aria-label`.
- [ ] Icon-only buttons have an accessible name.
- [ ] Decorative icons / images have `aria-hidden="true"` / empty `alt=""`.
- [ ] State is conveyed by more than colour.
- [ ] No `text-#hex`, no inline `style="color:…"`: use the existing
      token classes.
- [ ] External links: `rel="noopener noreferrer"` on `target="_blank"`.
- [ ] If untrusted HTML is rendered: sanitise first, then `{@html …}`.
- [ ] All user-visible strings go through `t(...)`; new keys added to
      **every** catalog under `src/lib/constants/messages/` (see
      [`i18n.md`](./i18n.md)).
- [ ] `aria-label` / `alt` / tooltip text routes through `t(...)` too.
- [ ] Terminology check: **prediction**, never "bet", even in copy.
